# 随记使用指南

[返回首页](../README.md) · [English](../README.en.md)

DSH 中由人管理的笔记与轻文档工作台。直接写段落、列表和待办，按需要允许 agent 一起维护。

当前版本 **dsh-jot 0.2.2**，验证宿主为 **DeepSeek Harness 0.2.0-rc.2**。[GitHub](https://github.com/Totoro-qaq/dsh-jot) · [版本记录](https://github.com/Totoro-qaq/dsh-jot/releases) · [npm](https://www.npmjs.com/package/dsh-jot)

目标覆盖 macOS、Windows 和 Linux 的 Desktop／Web。0.2.2 已通过类型检查、142 项测试和构建，当前宿主验收与 0.2.0 的历史记录分开保存在[验证记录](VALIDATION.md)。Windows／Linux 快捷键做了浏览器平台模拟，真实操作系统验收尚待补齐。

## 已实现

- 左侧导航「随记」打开完整工作台，无需先选聊天。
- 官方右侧栏的「随记」入口打开窄栏，在笔记列表与正文之间切换；不占用聊天输入框的按钮区。
- 直接编辑正文、标题、粗体、斜体、下划线、列表和可勾选待办，不要求输入 Markdown 语法。
- 插入表格、编辑单元格、增删行列；七种文字颜色、六种永久高亮颜色及清除格式。
- 搜索标题和正文，标题命中优先，并显示命中位置附近的摘要。
- 最近显示全部置顶笔记和最近修改的 5 条非置顶笔记；全部笔记可按修改时间、创建时间或标题排序，只渲染视口附近的条目。
- 当前笔记内查找、上／下个匹配、单处／全部替换；全部替换可一次撤销，回收站只允许查找。
- 文件夹由用户自行创建、命名和管理。初始没有预设分类，未创建时隐藏分类选择。
- 自动保存、手动保存、草稿恢复、版本冲突提示与另存草稿。
- 删除进入回收站，可以恢复；删除文件夹保留其中笔记。
- 更多／右键菜单提供置顶、移动、复制、删除和导出；选择模式可批量移动或移到回收站。
- 从当前窗口选中文字或粘贴文字，摘录为新笔记或追加到已有笔记，保留用户填写的来源。
- 文件选择、粘贴截图、拖入图片／文件；管理附件、图片和 PDF 的基本预览与下载。
- 导出当前草稿为 TXT、Markdown、PDF 或 Word（DOCX）；带附件的 Markdown 自动打包为离线 ZIP。
- 「允许 AI 协作」默认关闭。用户始终可以增删改；开启后 agent 可用五个 Jot 工具。

## 界面与整理

随记的产品图标是竹青色笔记本、暖白纸页与金杏色书签；新建、保存、附件、表格等操作使用统一的 K3 线条图标。摘录使用选区标记，剪切仍保留系统的 Command／Ctrl+X 行为。

- 在「文件夹操作」中新建文件夹；选中具体文件夹后可改名或删除。文件夹可选，删除文件夹会保留笔记。
- 在「列表选项」中选择按修改时间、创建时间或标题排序，以及进入／结束多选。「最近」未搜索时固定按修改时间排序。
- 进入多选后，工具条提供当前列表全选、移动和移到回收站；结束多选回到普通浏览。
- 正文工具栏保留格式、核对清单、查找和表格。窄容器以图标显示，名称仍通过提示与可访问标签提供。

界面沿用 DSH 的系统字体、主题与字号缩放，完整页标题、笔记标题和列表摘要保持层级。入口与侧栏继续使用 DSH 公开接口。

侧栏的浮出和停靠由 DSH 原生面板提供。本版不常驻悬浮球，不依赖 better-sidebar。

已实现功能、后续候选和暂缓项统一记录在 [功能清单](../PRODUCT.md#功能清单)。源码实现与真实宿主验收分别记录。

## 安装

```sh
# 桌面客户端
dsh plugin --profile desktop add dsh-jot

# Web UI
dsh plugin --profile web add dsh-jot
```

安装后重启对应 Host。官方 Desktop 可通过应用菜单「管理 dsh 命令…」启用其内置 CLI。Desktop 与 Web 使用独立 Profile；给 Web 安装不会自动给 Desktop 安装。

## 构建和本地安装

Node.js `^22.19.0 || >=24`，pnpm 11。

```sh
git clone https://github.com/Totoro-qaq/dsh-jot.git
cd dsh-jot
pnpm install --frozen-lockfile
pnpm check
pnpm pack:check
pnpm pack --pack-destination artifacts
```

将生成的 tarball 装到需要使用的 Profile：

```sh
dsh plugin --profile desktop add /absolute/path/to/dsh-jot/artifacts/dsh-jot-0.2.2.tgz
# Web 使用 --profile web
```

将路径替换为实际生成的文件，再重启对应 Host 并重新加载界面。

开发预览使用相同数据层、HTTP 适配器和编辑组件：

```sh
pnpm dev
```

打开 `http://127.0.0.1:4178`。预览数据放在仓库 `.jot-dev/`，与真实 DSH 笔记分开。预览是 UI 调试入口，真实插件使用 DSH 的认证机制。

## 常用快捷键

正文编辑以 macOS 的 Command、Windows／Linux 的 Ctrl 为主修饰键：

| 操作 | macOS | Windows／Linux |
| --- | --- | --- |
| 复制／剪切／粘贴／全选 | Command + C／X／V／A | Ctrl + C／X／V／A |
| 撤销／重做 | Command + Z／Shift + Command + Z | Ctrl + Z／Ctrl + Shift + Z；另支持 Ctrl + Y |
| 粗体／斜体／下划线 | Command + B／I／U | Ctrl + B／I／U |
| 当前笔记查找／保存 | Command + F／S | Ctrl + F／S |

剪贴板操作保留系统与编辑器的原生处理，格式和撤销／重做由编辑器按焦点处理。工作台选中笔记时，Mod+F／S 查找或保存当前笔记；菜单和对话框保留自己的按键处理。列表使用方向键、Home、End 和 Enter／Space；选择模式下 Enter／Space 切换勾选。菜单和对话框支持 Escape 与键盘焦点管理。

macOS／Windows Desktop 会先处理宿主绑定。正文聚焦时，随记使用 DSH 公开的 `shortcuts.registerFixed` 临时保留 Mod+B；macOS 的撤销／重做另通过公开 `shortcuts.register` 路由到正文历史，避开 Electron Edit 菜单的键盘拦截。失焦或卸载清理这些绑定，不修改用户设置。Web／Linux 保留本地编辑器优先处理。Native 定义同步是异步 IPC，协议测试通过不代表六种环境均已完成实机验收。新建笔记没有占用 DSH 新会话的 Mod+N。

已在真实 Web Host 与独立背景装饰／侧栏测试插件检查共存，测试后已移除夹具。随记使用独立注册 ID 和限定范围的样式，正文背景跟随宿主主题。替换宿主布局、使用全局 CSS 或重用相同 ID 的其他插件仍需逐个测试。

## 表格操作

点击单元格后，表格顶部的「⋯」管理当前列，左侧的「⋯」管理当前行；可以在前后插入，也可以删除所选行列。右侧和底部的「＋」分别追加最后一列和最后一行，位置不跟随文字光标。

拖动列与列之间的边界调整宽度，保存后再次打开会保留。「表格选项 → 自动适应宽度」清除整张表的手动列宽，重新按可用空间布局。行高随内容自动撑开；多列表格在自己的区域内横向滚动，不撑宽整个侧栏。当前不提供整体缩放或行高拖动。

表格最多 200 行、50 列，还受到笔记总节点数与 1 MiB 容量限制。新增操作在超过容量前拒绝；拖动列宽若因新增元数据超限，会还原原列宽并保留正文输入。回收站中的笔记不能调整表格。持久化兼容合并单元格，但当前没有合并／拆分按钮。

## 附件与导出

附件默认单文件最多 **20 MiB**，同一数据目录累计 **500 MiB／1,000 个附件**；界面每次最多添加 20 个文件。配置 `attachmentMaxBytes`、`attachmentMaxTotalBytes` 可调整字节额度，数量上限仍为 1,000。附件存入受管理的本地文件，只在正文保存 ID，不保存任意文件路径。

| 类型 | 上传后如何查看 |
| --- | --- |
| PNG、JPEG、GIF、WebP | 正文图片及预览弹窗 |
| PDF | 预览弹窗，依赖 DSH／浏览器的 PDF 查看器 |
| Word、Excel、PPT、Markdown、TXT、SVG、音视频等 | 文件卡片与下载；当前没有 Office 或飞书文档预览 |

上传没有扩展名白名单；支持保存文件不代表能够解析或预览其内容。

PNG、JPEG、GIF 和 WebP 按实际字节识别后可显示为图片；图片边长最多 10,000 像素、总像素最多 4,000 万。PDF 使用宿主／浏览器的 PDF 查看能力预览；其他格式提供文件卡片和下载。删除正文中的附件引用或将笔记移到回收站不会立即删除附件二进制，目前没有附件清理界面。搜索索引标题和正文中的文件名／说明，不解析 PDF 正文或做 OCR。

| 格式 | 导出内容 |
| --- | --- |
| TXT | 标题、正文、列表／待办状态、表格文字和附件名称说明 |
| Markdown | 格式、列表／待办及表格；有附件时返回 ZIP，包含 `note.md` 与 `assets/`，链接不依赖 DSH 登录 |
| PDF | 中文字体嵌入、常用样式、矢量待办框、分页表格、页码和 PNG／JPEG 图片 |
| Word（DOCX） | 文字格式、编号列表、待办状态、表格及 PNG／JPEG 图片 |

导出使用当前草稿，不要求先覆盖保存。每次最多引用 100 个不同附件，附件原始字节总量和最终导出文件均不得超过 50 MiB。PDF 超过 8 列的表格改为带行／列标识的文字；合并单元格内容保留，但合并边框不完全还原。表格内的图片在 PDF 表格后带说明显示。Markdown 使用安全 HTML 表达合并单元格，DOCX 保留合并结构。PDF／DOCX 对 GIF、WebP 和普通文件保留名称说明，不嵌入这些文件。

PDF 包含 `assets/fonts/NotoSansSC-Regular.otf`、`NotoSansSC-Bold.otf`，离线使用，不依赖系统安装中文字体；字体按 [SIL Open Font License 1.1](../assets/fonts/OFL.txt) 分发。DOCX 字体显示仍由阅读器和设备的字体决定。导出提供文档结构和基本样式，不声明与编辑器逐像素相同。

## Agent 协作

用户在界面打开开关后可使用：

| 工具 | 用途 |
| --- | --- |
| `jot_list` | 搜索笔记，返回有界的摘要列表 |
| `jot_read` | 读取一篇笔记及其版本 |
| `jot_create` | 记录用户要求保存的文字 |
| `jot_update` | 基于当前版本追加或修改文字 |
| `jot_delete` | 将笔记移到回收站 |

每次调用都会检查最新开关状态；agent 无法通过 Jot 工具开启自己的权限。修改和删除要求精确的 `revision`，避免覆盖其他编辑。追加文字保留已有文档格式；替换正文会转换为普通段落。

开关控制的是 Jot 提供的工具，不是系统级文件访问权限。笔记不会自动注入每轮模型请求；模型通过明确的读取或搜索获取内容。

## 数据与冲突

默认数据目录为 `$DSH_HOME/jot`，未设置 `DSH_HOME` 时为 `~/.dsh/jot`。可以在插件配置中设置 `directory`。同一数据目录由人和 agent 共用，文件锁保护跨进程修改。

- `jot.json`：笔记、文件夹和开关状态。
- `jot.json.bak`：上一次保存前的有效状态。
- `.jot.lock`：写入／读取协调锁，记录 owner PID。
- `attachments/`：受管理的附件二进制、`manifest.json` 和附件协调锁。

单篇 RichDoc JSON 最多 1 MiB、正文最多 200,000 个 JavaScript 字符长度单位；整库笔记状态最多 32 MiB。表格最多 200 行、50 列，仍受单篇文档的整体限制。备份时保留整个数据目录；浏览器恢复草稿另外保存在该界面的 Local Storage。

损坏或未知版本的数据会明确拒绝读写，保留原文件，不静默覆盖为空库。异常退出若留下锁，应先确认锁中的进程已经结束，再移走该锁。不要以清空笔记文件解决锁冲突。文件替换是原子的；本版本不声明断电时最近一次提交必然保留。

## 验证与边界

`pnpm check` 覆盖类型检查、持久化／跨进程并发／版本冲突／agent 门控／HTTP 认证边界和客户端草稿保护，并生成 Host 与 Client。`pnpm pack:check` 检查模块工厂、包身份和共享 React 导入。

真实宿主、界面及打包验证记录见 [验证记录](VALIDATION.md)。共享 Web 插件接口不能替代 Desktop 原生壳的独立实测。

本版不包含云同步、实时多人编辑、修改历史、附件垃圾回收、自由绘图／批注、自动总结后台任务或自定义快捷键配置。批量管理逐条检查版本并执行；失败前已完成的操作会保留，不是整批事务。
